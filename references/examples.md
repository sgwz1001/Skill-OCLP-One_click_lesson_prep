# 命名规范详解与案例

## 标准结构

```
文件名-文件类型-时间-v版本号&备注.扩展名
```

| 字段 | 含义 | 说明 |
|------|------|------|
| 文件名 | 主题 / 内容主体 | 自由描述，如「三方共同运营合同」「平台首页效果预览」 |
| 文件类型 | 类型描述（非扩展名） | 如「合同」「数据表格」「效果预览网页」 |
| 时间 | 创建 / 修订日期 | 格式 `YYYYMMDD`，如 `20260701` |
| v版本号 | 版本 | `v1` / `v2` 主版本；`v1.1` / `v1.3` 次版本 |
| 备注 | 变更说明 | 可选，`&` 后接文字，如「按照企业规范与老国标版本」 |
| 扩展名 | 真实扩展名 | 如 `docx` / `xlsx` / `html` |

> 注意：「文件类型」是中文类型描述，与扩展名分开。例如「数据表格」类型的文件扩展名是
> `xlsx` 而不是 `excel`；下方用户原始案例里的 `.excel` 视为笔误，应替换为真实扩展名。

## 版本递增规则（最关键）

| 场景 | 触发条件 | 版本变化 | 日期 |
|------|----------|----------|------|
| 首次创建 | 目录中无同名主题 | `v1` | 当天 |
| 跨天再改 | 与最新版本日期不同（哪怕只改一点点） | 主版本 +1（v1→v2） | 更新为当天 |
| 大篇幅重构 / 大改 | 同日或跨天，内容大改 | 主版本 +1（v2→v3） | 当天或更新 |
| 同日小幅多轮 | 同一天、多次小幅修改 | 次版本 +0.1（v1→v1.1→v1.2） | 不变 |

要点：
- **跨天一律主版本 +1**，无论改动大小。
- **同日** 才区分：大改 → 主版本 +1；小改 → 次版本 +0.1。
- 主版本进位时，次版本清零（v1.3 跨天后变为 v2，不是 v2.3）。

## 用户原始案例（直接取自需求）

1. `国资资产九大类型-数据表格-20260705-v1&按照企业规范与老国标版本.xlsx`
   - 类型：数据表格；日期 20260705；v1；备注说明依据。
2. `三方共同运营合同-合同-20260701-v2.docx`
   - 类型：合同；日期 20260701；v2（说明此前已有 v1）。
3. `平台首页效果预览-效果预览网页-20260801-v1.3&微调了UI布局.html`
   - 类型：效果预览网页；日期 20260801；v1.3（同日多轮小幅修改）；
   备注「微调了UI布局」。
